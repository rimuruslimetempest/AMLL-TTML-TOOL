Submit to the marketplace

Themes and plugins are added by pull request. Nothing appears on this site until Rimurulover reviews and merges your change, and the same validation runs on your pull request.

Open a pull request Ask first with an issue

Submit a theme

  1. Build and test your theme

    Export it from Settings → Appearance → Themes, or write a theme.json that follows THEMES.md. Test it in the app, in both New and Classic UI, and with Performance mode on.

  2. Add the theme file and a preview

    Put the JSON in docs/registry/themes/<id>.json and a 16:9 preview in docs/assets/previews/<id>.svg (or .png). Keep the theme file under 2 MB.

  3. Add a registry entry

    Edit docs/registry/themes.json and add your id, name, author, version, description, tags, appearance, preview path, download path, SHA-256, performance level, and minimum app version. The SHA-256 is the hash of the exact JSON file.

  4. Run the checks

    node scripts/validate-theme-registry.mjs must pass. The same check runs automatically on your pull request and fails on a bad field, a hash mismatch, a missing preview, or a theme that contains remote URLs or scripts.

  5. Wait for review

    Open the pull request and describe the theme in your own words. Merging is the only thing that publishes it. Please do not bump the version for cosmetic edits; use a new version when the palette changes.

Theme registry entry example

{
  "id": "aurora",
  "name": "Aurora",
  "author": "your-github-name",
  "version": "1.0.0",
  "description": "A short description in your own words.",
  "tags": ["dark", "green", "calm"],
  "appearance": "dark",
  "preview": "assets/previews/aurora.svg",
  "download": "registry/themes/aurora.json",
  "sha256": "<64 lowercase hex characters>",
  "size": 12345,
  "performance": "light",
  "minAppVersion": "1.0.0",
  "verified": false
}
!
Themes are CSS and JSON only. Do not include JavaScript, remote fonts, @import from another site, or images loaded from the network. Those entries are rejected by the validator and by the app's importer.

Submit a plugin

Plugins run as sandboxed WebAssembly. A plugin can add an import format, an export format, or a lyric tool; it cannot inject JavaScript into the editor.

  1. Build against API 2.0

    Compile a .wasm module that exports allocate, run_importer, run_exporter, or run_tool, and add a plugin.json manifest that declares its type, permissions, and slots. See PLUGINS.md for the full contract.

  2. Add the bundle

    Create docs/registry/plugins/<id>/plugin.wasm and plugin.json next to it. The module is capped at 2 MB and the manifest must match the registry entry exactly.

  3. Add a registry entry

    Edit docs/registry/plugins.json with the id, name, author, version, description, tags, type, permissions, slots, download path, SHA-256, byte size, minimum app version, and addedAt date.

  4. Run both validators

    node scripts/validate-marketplace.mjs runs the theme and plugin checks. Your pull request fails on a hash mismatch, a bad file size, a missing manifest, a permission outside the allowlist, or a module without the WebAssembly header.

  5. Wait for review

    A maintainer reads the module's permissions and behavior before merging. Nothing is installed automatically, and a bad entry can be marked deprecated without touching anyone's installed copy.

Plugin registry entry example

{
  "id": "lyric-normalizer",
  "name": "Lyric Normalizer",
  "author": "your-github-name",
  "version": "1.0.0",
  "description": "Trims stray spaces and normalizes word order in tool runs.",
  "tags": ["lyrics", "tool"],
  "type": "tool",
  "apiVersion": 2,
  "permissions": ["lyrics:read", "lyrics:write"],
  "slots": [],
  "download": "registry/plugins/lyric-normalizer/plugin.wasm",
  "sha256": "<64 lowercase hex characters>",
  "size": 24576,
  "minAppVersion": "1.0.4",
  "addedAt": "2026-11-24",
  "verified": false
}
!
WebAssembly only for now. The marketplace does not run arbitrary JavaScript or CSS inside the app. A plugin must declare every permission it uses, and permissions are shown before install. Modules that load remote code or hide their behavior are rejected.

Review and removal

Rimurulover reviews every entry. A theme or plugin can be removed or marked deprecated if it breaks the app, contains content that does not belong to the author, or stops matching its published hash. Removing an entry does not reach into anyone's installed copy; people can delete it in Settings.
